# Manim video creator

Create only the content the user requests, with accurate mathematics, restrained animation, and stable typography. Use concise Spanish titles unless another language is requested. Do not add unsolicited captions, explanatory labels, legends, rules, or decoration. Retain purposeful existing elements when editing.

## Workflow

1. Read applicable repository instructions and the target scene and helpers before editing. Check the actual Manim environment and font availability through read-only inspection. The inspected environment uses **Manim Community 0.17.3**, not ManimGL; do not copy `manimlib` APIs or configuration keys into it.
2. Read [typography.md](references/typography.md) before selecting text, equation, or number typography. It records primary sources, exact settings, local dependencies, and declared fallbacks. Use [typography-example.md](references/typography-example.md) for a copyable CE-compatible template and formatting functions. Do not silently substitute fonts or describe the result as an exact match when a fallback is active. Normal CMU Serif Roman (`NORMAL` weight/slant, disabled ligatures) remains the default for letters, digits, and punctuation, with zero text stroke. The optional symbol emphasis below is an explicitly requested local exception to the reference's no-synthetic-thickening guidance, never a new default.
3. Reuse the appropriate infrastructure. Stage 1 uses `assets/manim/algebra/stage1_arithmetic_foundations/common.py`: `TopicScene`, `render_section(self, *, standalone=False)`, `source_file = __file__`, a literal stable `output_identity`, and `planned_seconds`. Use `move`, `pause`, `finish_beat`, and the existing explicit clock; preserve timing budgets or update affected budgets within the requested work. Reuse layout and transition helpers where appropriate, adapting typography locally when their Segoe UI defaults conflict with the selected reference.
4. Implement and review the scene source without executing it. Check endpoints, signs, scale, layout bounds, mathematical equality, state transitions, updater order, cleanup, and both standalone and combined invocation paths by reading the code. Report changes, the calculated MP4 destination when applicable, active typography/fallbacks, and any unperformed verification.

## Render-command documentation

Every scene created or modified through this skill must include a copyable render command in its opening module docstring. State that it runs from Windows CMD at the repository root. Use the actual repository-relative source path and renderable scene class, following:

```text
python -m manim -ql <source-path> <SceneClass>
```

Quote source paths when necessary. Preserve existing documented quality, frame-rate, and other render options; use `-ql` when introducing a command without an existing preference. Keep the documented source path and class accurate after renames. Include a combined-lesson command only when applicable; do not add standalone scenes to the combined lesson.

Documenting a command does not authorize executing it. Rendering, previews, and tests remain subject to the explicit authorization requirements in the execution boundary below.

## Animation and layout invariants

- Ordinary object repositioning, including during glyph morphs, should use explicit cubic Bézier trajectories with deliberately chosen control points. Preserve exact endpoints and upright labels; apply easing once to trajectory progress, join multiple cubics with continuous tangent direction, and allow clearance for changing bounds and simultaneously moving neighbors. Spatial trajectories are separate from glyph-outline interpolation and mathematical geometry: preserve intentional rotations, circular swaps, value-driven geometry, and straight arrow shafts; do not add visible paths.
- Only when explicitly requested, emphasize equals and U+2212 minus signs with a restrained, symbol-only outline stroke matching the fill; keep letters, digits, punctuation, and titles unchanged. Preserve optical positions, shared baseline offsets, fixed anchors, and mathematical spacing: never stretch, duplicate, offset, or switch whole runs to bold/semibold to simulate weight. As a separate explicitly requested style, shorter U+2212 glyphs may use local horizontal compression (start near 75% width) about their existing center, preserving vertical metrics, baseline, optical center, stroke emphasis, and surrounding layout. This is a scoped exception to guidance against stretching glyphs; do not apply it to other characters by default, especially the equals sign. Compress only the cached minus or the minus within a fully shaped label. Preserve the spacing policy and sign-driven number-field movement; use the shortened width in the existing clearance formulas. Scale the stroke to font size and review stroke-expanded visible bounds (ordinary VMobject bounds exclude strokes) for overlap and minus-to-digit clearance. Preserve the equals sign's outline, position, internal gap, and equal thickness on both bars. Style cached symbols before copying; retain fill and stroke through stable-slot `match_style` updates. For axis labels, shape and position the complete label before compressing/styling only its minus glyph so other glyphs do not move.
- Use one authoritative mathematical state. When values are displayed at limited precision, compute the quantized state once and use it for both glyphs and the geometry they assert. Keep exact arithmetic for derivations; choose deliberate display precision rather than falsifying an equality through rounding. At zero, remove a signed arrow's shaft and tip instead of inventing a direction or nonzero length.
- For signed arrows, coordinate shaft thickness with head length, width, and curvature. Explicitly requested minimalist heads may use narrow, elongated, open silhouettes: a straight shaft and two mirrored inward-curving cubic Bézier branches, uniform white strokes, and no filled triangle or decoration. Define concavity relative to the straight tip-to-rear chord: each branch must lie toward the shaft axis from that chord, not bulge outward. Build CE-compatible `VMobject` paths in local coordinates (tip at the origin, rear along negative x), reflect the branches exactly about the shaft axis, and orient the complete convention consistently for either sign. Keep head length clearly greater than total width, a mathematically sharp shared tip at the exact represented endpoint, and the shaft from mathematical zero to that tip without overshooting. Prefer rounded exposed rear caps only when the installed renderer can configure them independently of the sharp forward join. Inspect installed cap/join source first: CE 0.17.3 Cairo supports `LineJointType.MITER` but exposes no VMobject line-cap API; use default butt rear caps, disclose the limitation, and do not add endpoint dots. A stroked miter projects ink beyond its exact centerline vertex; disclose this stroke-bound limitation rather than claiming exact ink bounds. A custom filled curved head remains a separate explicitly requested option; only for that style close the path and terminate the shaft inside its fill. For either style, constrain head dimensions and curvature smoothly for short nonzero arrows, scaling the common stroke as needed without exaggerating magnitude or imposing a minimum arrow length. Preserve consistent nonzero path topology and stable shaft/head slots (both open branches belong in the head slot); update points/styles in place without replacing submobjects, including across sign changes. Completely clear both slots at zero. `01_numbers-arrows.py` uses local nominal stroke width 5 uniformly for the shaft and both head branches, retaining the common short-arrow stroke scaling; this is scene-specific, not a universal default. It uses nominal head length 0.34 and total width 0.14 (about 2.43:1), with head length smoothly capped below 48% of arrow length. Its upper rear-to-tip cubic has controls `(-0.72, 0.20)` and `(-0.28, 0.12)` between `(-1, 0.5)` and `(0, 0)` in head-length/total-width units; reflect for the lower branch. Keep these proportions local unless shared styling changes are requested.
- For dynamic equations and numeric readouts, choose explicitly between **fixed-column mode** for stationary digit centers/decimal positions and **compact equation mode** for tightly spaced content around an anchored equals sign. Plan capacity for the full range, sign, and precision before revealing the equation; preserve structural anchors and the shared baseline. Never recenter the whole equation or rescale it per value. Suppress unnecessary trailing decimals, grouping separators unless needed, and negative zero. These modes do not impose dynamic-layout rules on ordinary prose or unrelated static equations.
- For rotating arrows, rotate the arrow only. Position separate upright labels from the arrow's current midpoint and a normalized perpendicular offset; guard zero length. Never rotate a group containing the glyphs. See the existing `rotation_label` in `03_signed_multiplication.py`.
- For changing displays, reuse/adapt the cached glyph and stable `VMobject` slot approach in `01_numbers-arrows.py` (`CenteredNumber`) or the integer-oriented `FixedNumber` in `03_signed_multiplication.py`. Preserve the original shared glyph baseline, size slots for the full range, and retarget only on changed display state; advance only active visual transitions between state changes. Preserve the moving family by updating existing slots rather than replacing their submobjects during a play. Do not import a numbered scene merely for its typography; copy a small relevant pattern locally or extract a helper only within the user's scope.
- In dynamic displays, when smooth symbol changes are requested, morph replacement glyphs directly within their existing `VMobject` slots. Preserve structural anchors, semantic slot identities, original baseline offsets, cached shapes, and symbol-specific fill/stroke styles. Keep unchanged glyph shapes untouched; in compact equation mode their positions may follow the numeric field. Use CE 0.17.3-compatible point alignment/interpolation on working copies, never the original cache. Account for contour compatibility (CE's equal-total-point shortcut can skip contour alignment), use one visible outline per slot, and restore exact target points/styles at completion to discard alignment-only null contours and lingering strokes.
- Drive dynamic glyph interpolation from the existing ordered updater lifecycle; never start plays from updaters or add per-symbol plays/waits. Ordinary occupied-to-occupied replacement stays opaque without disappearance/reappearance or overlay ghosts. Genuine entry/removal may grow/shrink and fade continuously within its semantic slot. Fixed-column mode retains reserved space; compact equation mode may smoothly open/reclaim space in coordination with the glyph transition, maintaining clearance from adjacent glyphs. For unscheduled interrupted transitions, continue from visible points/style without jumps, queues, or accumulating delay; predetermined sequences use the deterministic phase convention below.
- Mathematical state remains authoritative during glyph interpolation: quantize once for numerical targets and associated geometry. A visual morph between consecutive targets is not another numerical state: do not interpolate geometry toward a future target, delay it, or change sweep durations, reading pauses, or timing budgets. Restore exact outlines/styles (or completely empty slots) and final layout before reading holds and updater cleanup.
- **Fixed-column mode:** for readouts whose digits or decimal positions must remain stationary, reserve semantic sign, integer, separator, and fractional columns with an explicit column-to-slot mapping and a fixed anchor. Size the sign column from actual cached glyph bounds plus explicit clearance. Right-align integer digits within reserved columns; preserve fixed centers, the shared baseline, and original vertical offsets. Hide unused columns and trailing fractional zeros without collapsing space. Position the complete reserved field once, never from each value's visible ink. Retain cached glyphs and stable `VMobject` slots with in-place geometry/style updates.
- **Compact equation mode** (used by `01_numbers-arrows.py`): keep the equals sign stationary and place the variable and first visible numeric symbol near it with balanced explicit gaps. Use actual glyph bounds, including stroke expansion where emphasized, for equals-to-number and minus-to-digit clearance. Reclaim unused sign space for positive/zero values; smoothly translate the numeric field right/left as a minus enters/leaves and as integer digit count changes. Preserve fixed internal digit advances, the shared baseline, semantic slots, and cached glyphs. The decimal travels with the field and never jitters independently. Coordinate layout interpolation with glyph morphing, including entry/removal, so intermediate symbols remain separated; never recenter the equation. Fixed absolute digit centers/decimal positions apply only in fixed-column mode.
- **Requested changing-symbol sequences:** each target-to-target interval holds the reached target's exact shape and layout for the first **70%**, then smoothly transitions to the next target during the final **30%**, completing exactly at the next boundary. Apply the same phase to replacement, entry/removal, and numeric-field movement; unchanged shapes may translate with the layout. Derive boundaries deterministically from the existing sweep timeline and quantization crossings, respecting its rounding rule, both directions, shortened endpoint intervals, and reversals. Do not estimate intervals from variable frame times or queue independent digit animations. Complete each endpoint before its reading pause, hold it exactly throughout, and start the next sweep's phases only when motion resumes. Never morph during explicit holds. Scope this convention to requested changing-symbol sequences; preserve unrelated scene transitions, pauses, and total duration.
- Preserve `render_section` reuse by `00_preliminaries.py`. Do not add a standalone interlude to the combined lesson unless requested. Keep imports file-relative/root-anchored as the neighboring scenes do. Avoid global `Text.set_default`, `MathTex.set_default`, or import-time output/typography changes that leak into other sections. Clear section-owned updaters before transitions and resolve exact final states before holds.

## Destination integration

Read and use [manim-output-path](../manim-output-path/SKILL.md) **only to calculate the final repository-relative MP4 destination** for a source under `assets/manim/`. Resolve the existing source's literal class attribute `output_identity` through `assets/manim/output_paths.py`. This is a permanent normalized `.mp4` path relative to `../manim_media/videos/`, independent of source numbering, filename, scene name, or quality. For a new scene explicitly choose a unique identity once; for an existing scene capture its actual final MP4 and partial-movie destinations before migrating to a declaration. Never change an identity when renaming a source. Missing files or identities require clarification, never a guessed filename-based destination. Partial movies use `partial_movie_files/<identity stem>/{quality}/{scene_name}/` beside the MP4.

The path skill authorizes no edits, configuration, directory creation, or rendering. Any Python changes to implement that destination are separate work within the user's video task. Stage 1 already configures output at scene initialization through `ArithmeticScene`, so preserve the owning scene's `output_identity` when combined scenes import topic modules. Use `output_destination` and `partial_movie_directory` from `assets/manim/output_paths.py` for runtime configuration. Source renames may change only the source-path argument of existing Windows CMD render commands; preserve class names, options, quality, frame rate, and all scene behavior. Update loader imports and documentation references separately. The older `assets/manim/algebra/output_config.py` uses a different destination convention; do not copy it uncritically or rewrite shared configuration outside scope. For a path-only request, use the path skill alone and return its required path-only response.

## Execution boundary

A request to render does not also request tests, and vice versa. Do not automatically invoke Manim, LaTeX compilation, preview tools, imports that execute scenes, or validation scripts after authoring.
