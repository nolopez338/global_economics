# LaTeX integration

Use this reference only for a LaTeX source. Inspect the document class, included files, local macros, package options, and build instructions before selecting an implementation. These are conditional techniques, not required commands or a fixed template.

- Within a numbered Introduction, a normal `\subsection{Key terms and highlight guide}` inherits numbering. Place a convention-consistent `\label` at the heading. For unnumbered or custom structures, follow the existing hierarchy and contents conventions rather than forcing numbering.
- Find the existing legend macro, registry, or input and its callers before moving it. Relocate its invocation or adapt the underlying entry; avoid a second invocation that prints the same legend. Keep unrelated definitions intact and retain labels when moving content.
- Reuse existing text-mode and math-mode highlight wrappers appropriately. Inspect whether wrappers work inside table cells, moving arguments, and mathematical expressions. Avoid nesting them or introducing fragile commands into headings or bookmarks unnecessarily.
- A disabled highlight wrapper must still emit its argument. Reuse existing toggle logic and preserve its committed state. If a toggle must be added, scope it to the document or appropriate shared styling layer; do not introduce competing switches. A boolean or style override is suitable only if it follows local conventions.
- Use a non-floating table when a float would defer the guide past the material it introduces. Choose column widths and paragraph wrapping that fit the text block. Use an existing keep-together or space-reservation mechanism when practical; a minipage or unbreakable box must not exceed the page. Restructure an oversized table before reducing type size. Do not add packages without checking existing equivalents and compatibility.
- Build with the established engine and toolchain, including required reruns for references and contents. Inspect warnings for undefined references, duplicate destinations, and overfull boxes alongside rendered pages. Verify actual PDF links where supported.
- Validate both toggle states using isolated source copies or supported build overrides. Preserve relative inputs and asset paths, keep output directories separate, and confirm the original source toggle remains unchanged. Remove only generated temporary artifacts, following the project's cleanup conventions.

- For document-wide markup, renderer integration, diagram styling and toggle validation, follow `math-practice-highlights` after this skill establishes the guide and semantic mapping. If both are active, resume the next unfinished responsibility without reinvocation. Reuse the same wrappers and authoritative registry entry. The companion's repository-specific paths apply only in that repository.
- In legends, highlight concept names, complete notation and representative values with the agreed role; in composite formulas retain component roles and leave operators outside wrappers. Inspect affected consumers before editing shared definitions.
