# LaTeX integration

Use this reference only for a LaTeX source. Inspect the document class, included files, local macros, package options, and build instructions before selecting an implementation. These are conditional techniques, not required commands or a fixed template.

- Use native headings and labels for both tables, without hard-coding subsection numbers or requiring a fixed opening title. A brief heading or lead-in can introduce the concise legend. Preserve existing targets when relocating tables. Follow the authoring skill for course-specific section placement.
- Find the existing legend macro, registry, or input and its callers before moving it. Relocate its invocation or adapt the underlying entry; reuse each complementary table for its intended purpose rather than printing the same complete legend twice. Keep unrelated definitions intact and retain labels when moving content.
- Reuse existing text-mode and math-mode highlight wrappers appropriately. Inspect whether wrappers work inside table cells, moving arguments, and mathematical expressions. Avoid nesting them or introducing fragile commands into headings or bookmarks unnecessarily.
- A disabled highlight wrapper must still emit its argument. Reuse existing toggle logic and preserve its committed state. If a toggle must be added, scope it to the document or appropriate shared styling layer; do not introduce competing switches. A boolean or style override is suitable only if it follows local conventions.
- Use a non-floating table when a float would defer the guide past the material it introduces. Choose column widths and paragraph wrapping that fit the text block. Use an existing keep-together or space-reservation mechanism when practical; a minipage or unbreakable box must not exceed the page. Restructure an oversized table before reducing type size. Do not add packages without checking existing equivalents and compatibility.
- Build with the established engine and toolchain, including required reruns for references and contents. Inspect warnings for undefined references, duplicate destinations, and overfull boxes alongside rendered pages. Verify actual PDF links where supported.
- Validate both toggle states using isolated source copies or supported build overrides. Preserve relative inputs and asset paths, keep output directories separate, and confirm the original source toggle remains unchanged. Remove only generated temporary artifacts, following the project's cleanup conventions.

- For document-wide markup, renderer integration, diagram styling and toggle validation, follow `math-practice-highlights` after this skill establishes both table designs and their shared semantic mapping. If both are active, resume the next unfinished responsibility without reinvocation. Reuse the same wrappers and authoritative registry entry. The companion's repository-specific paths apply only in that repository.
- In legends, highlight concept names, complete notation and representative values with the agreed role; in composite formulas retain component roles and leave operators outside wrappers. Inspect affected consumers before editing shared definitions.

## Complementary table layout

Use `tabularx` or existing paragraph-column equivalents with non-floating placement when ordering matters. Preserve the three-column concise schema and four-column detailed schema from SKILL.md; translate headers consistently. Use top-aligned, ragged-right prose cells. For the detailed final column, short `\textbullet\ Example 1: ...\par` entries work without a nested list's excess spacing. Link to existing example labels with the document's hyperlink commands. Include only relevant examples.

Keep the concise legend compact. Allow the detailed reference to continue with repeated headers across pages or opening Beamer frames; do not scale an overcrowded table into one frame. In Beamer, reserve final cell dimensions with stable overlays and establish the source situation before revealing its contextual interpretation. The closing concise legend is a distinct table with no reveals. Reuse notation and role macros across both designs, not a single identical table body.

For English use `Symbol or notation | Concept | Brief meaning` and `Symbol or notation | Concept | Definition | Meaning in the introductory examples`. Spanish equivalents are `Símbolo o notación | Concepto | Significado breve` and `Símbolo o notación | Concepto | Definición | Significado en los ejemplos introductorios`. Translate “Example 1” consistently as “Ejemplo 1” in Spanish.
